# Bingo Desktop

**在真实 React 项目上搭建页面、调整界面，并把设计改动带回代码。**

Bingo 是一款本地桌面可视化编辑器，把项目组件、设计画布、AI 编程助手和代码编辑放在同一个工作空间。你可以复用已有组件制作业务页面，在画布中调整布局与样式，预览效果，再将需要落地的修改保存到项目源码。

适合已有 React 项目的产品原型验证、界面改版和组件调试。界面支持简体中文与英文。

## 业务场景

| 场景 | 在 Bingo 中怎么做 | 可以得到什么 |
| --- | --- | --- |
| 验证新业务页面 | 从项目中选择按钮、表单、卡片等组件，组合成页面并调整属性 | 使用真实组件的页面原型，方便讨论内容与布局 |
| 调整现有界面 | 打开组件，修改文字、间距、颜色和排版；也可接入运行中的本地页面进行调整 | 可预览的界面改动，以及后续保存到代码的修改内容 |
| 探索多个设计方案 | 用多个页面和画框组织方案，复用组件，分别尝试布局与尺寸 | 可以切换查看和演示的候选方案 |
| 用 AI 辅助实现需求 | 把选中元素、组件、文件或图片加入对话，再描述需要的改动 | 结合项目上下文的画布操作或代码修改 |
| 调试和维护组件 | 查看组件属性、编辑源码、预览历史版本并按需恢复 | 从外观检查到源码修改的完整工作流程 |
| 持续迭代项目 | 将设计数据与项目一起保存，需要时通过 Git 携带到另一份克隆 | 可以继续编辑的画布、对话、资源和历史记录 |

## 核心功能

### 复用项目中的真实组件

打开本地 React 项目后，Bingo 会扫描组件，并加载组件预览和项目样式。你可以搜索组件、将其插入画布、调整可识别的属性，也可以打开组件源文件继续编辑。

工作区包含多个子项目时，可以先选择要打开的项目。缺少依赖时，应用会提示准备项目资源；安装完成后重新加载。

### 用画布组织页面与布局

通过页面、画框和图层管理界面结构，插入文本、图片、视频、图标和基础 HTML 元素。支持拖放、缩放、尺寸调整，以及横向、纵向和网格布局。

样式面板可调整排版、间距、背景、边框、圆角和阴影，也可以查看和编辑 CSS、样式类及所选内容的代码。通过不同画框尺寸检查页面在手机、平板和桌面尺寸下的表现。

首次打开没有设计记录的项目时，画布从一个空白页面开始。组件需要主动插入；再次打开项目会恢复已保存的页面与图层。

### 让 AI 结合页面和代码工作

在对话中描述需求，并附上当前选区、组件、文件或图片，让编程助手帮助创建组件、调整布局或修改代码。例如：

> 使用项目现有的卡片和按钮组件，搭建一个订单概览页，包含统计区域、筛选栏和订单列表。

> 将选中的表单改成上下排列，统一字段间距，并保留现有提交逻辑。

全局设置支持选择本机安装的 **Claude Code、Codex CLI、OpenCode 或 Grok Build**。使用前需完成所选助手的安装和登录，模型与凭据由对应助手管理。

对话历史会在本地保存。项目记忆可以保存经用户授权的项目规则，供同一项目的后续对话使用；自动整理长对话为可选功能，默认关闭，且取决于所选助手的支持情况。

### 预览效果，再保存到代码

通过预览窗口和原型演示查看页面，也可以在画布中添加实时预览，连接已经运行的本地开发地址。

**画布中的变化和项目源码分别保存。** 调整组件或实时页面后，需要执行相应的保存到代码操作，才能将修改写入源文件。部分修改可直接写入，组件合并或复杂改动需要编程助手参与；可视化组件保存流程会校验生成的代码。

你也可以复制所选内容为 React 代码，或在内置代码窗口中编辑。组件文件的历史版本支持查看源码、预览和恢复，便于比较与回退。

### 管理素材与设计参考

将图片、视频等素材添加到画布，使用项目配置的图标库，并通过剪贴板与 Figma 交换支持的设计内容。Figma 剪贴板导入受内容类型和资源可访问性限制，当前桌面版不提供 Figma 账号连接，需要账号授权的图片无法通过该流程导入。

### 在本地保留工作进度

项目标签页便于切换工作；内置终端可用于运行项目命令。设计页面、画布状态、对话、版本和上传资源保存在项目目录中，重新打开后可以继续工作。

Bingo 无需注册账号。组件构建和设计数据存储在本机；使用 AI、在线字体或外部资源时，仍会访问相应服务，AI 请求会使用提供给助手的项目上下文。

## 开始使用

1. **启动 Bingo，打开项目文件夹。** 如果检测到多个子项目，选择本次要编辑的项目。
2. **选择设计数据是否参与 Git 管理。** 添加项目时可勾选“在 Git 中忽略设计数据”，默认不勾选。
3. **完成项目准备。** 如果出现缺少依赖的提示，按提示准备项目资源并重新加载。
4. **搭建第一个页面。** 从组件或素材面板插入内容，使用图层和样式面板调整页面。
5. **按需启用 AI。** 在全局设置中选择已安装并登录的编程助手，把需要修改的内容加入对话。
6. **预览并保存成果。** 查看页面效果；需要修改项目源码时，执行保存到代码，或通过编程助手完成修改。

接入实时预览前，先启动目标项目的开发服务，再填入对应的本地地址。

## 数据保存与项目迁移

| 数据 | 保存位置 |
| --- | --- |
| 原型、画布状态、历史版本、对话及附件、项目记忆、预览图和上传资源 | 项目内的 `.bingo/design/` |
| 项目配置 | 可通过存储设置保存为项目内的 `.bingo/config.json` |
| 本机偏好、文件夹授权、凭据、项目列表和诊断记录 | Electron 的 Bingo `userData` 目录 |

需要从另一份克隆继续工作时，将整个 `.bingo/design/` 目录随项目提交。该目录包含对话和附件，是否纳入版本控制由你决定。添加项目时勾选“在 Git 中忽略设计数据”会将 `/.bingo/design/` 加入项目的 `.gitignore`；不勾选会保留已有 Git 规则。

从项目列表移除项目，默认保留源码和设计数据。只有勾选“同时删除项目设计数据”，才会删除 `.bingo/design/` 及当前应用中的旧版设计副本；项目源码、配置和 Git 设置会保留。

打开项目时，应用会按需复制当前 Bingo 配置目录中的旧版设计数据，保留原始副本作为备份，并优先使用已有的项目数据。Bingo 与 Bingo 使用独立的存储和运行约定，不会自动发现或迁移 Bingo 数据。

项目操作受当前项目的访问范围约束；需要访问额外文件夹时，可在项目设置中明确授权。当前版本提供本地工作流程，不包含云端协作、托管构建或 GitHub 账号连接。

## 从源码运行

准备 Node.js 与 pnpm（仓库声明的 pnpm 版本为 `9.0.0`），在仓库根目录执行：

```bash
pnpm install
pnpm dev
```

修改后运行项目检查与预览构建：

```bash
pnpm check
npm --prefix preview run build
```

`pnpm check` 会执行 Node 测试并构建 Electron 主进程、预加载脚本和渲染进程。构建产物位于 `out/` 与 `preview/dist/`，均已被 Git 忽略。

### 构建 macOS 安装包

```bash
pnpm dist:mac
```

该命令生成 Apple Silicon 测试安装包，将带时间戳构建编号的 DMG、ZIP 和 blockmap 输出到 `release/`，并清理临时应用目录。使用此命令打包；离线构建时可通过 `BINGO_ELECTRON_DIST` 指定缓存的 Electron 分发 ZIP。

安装后将应用保留在 `/Applications/Bingo.app`，更新完成后弹出安装卷；源码开发使用 `pnpm dev`。历史版本可保留为 DMG 或 ZIP，避免留下多个解压后的应用副本。

本地构建使用临时签名，正式分发仍需 Developer ID 证书和 Apple 公证。运行依赖保留为普通文件，以便本地编译和搜索能启动 esbuild、ripgrep 等可执行文件。

### 代码结构

```text
packages/
  workspace/  项目管理、设置、数据接口与组件加载
  compiler/   组件扫描、TSX 编译、代码生成与画布数据
  editor/     画布、样式面板、预览、代码编辑与 AI 对话
  ui/         通用界面组件
  i18n/       中英文界面文案与本地化
src/
  main/       本地存储、编译、AI、MCP 与终端服务
  preload/    桌面应用接口桥接
  renderer/   桌面入口、样式与运行兼容层
preview/      组件预览与验证
tools/        恢复、打包与诊断工具
```

### 排查问题与维护资料

加载项目遇到问题时，可先查看 [项目加载问题说明](docs/project-load-errors.md)。本地诊断记录可通过以下命令读取：

```bash
node tools/diagnostics.mjs recent --json
node tools/diagnostics.mjs show inc_<UUID> --json
```

更多内容见 [诊断说明](docs/diagnostics.md)、[对话恢复说明](docs/chat-resilience.md) 和 [代码审查与清理记录](docs/plans/code-review-and-cleanup.md)。

当前维护代码基于已发布的 Bingo 0.0.146 应用包重建，部分文件仍保留重建标记或 React Compiler 产物。进行大范围结构调整前，请阅读 [代码恢复说明](RECOVERY.md)。

需要重新提取历史源码时：

```bash
pnpm rebuild:source
node tools/rebuild.mjs --output /tmp/bingo-recovered
```

恢复脚本默认输出到 `recovered-source/`，不会写入当前维护源码。`_raw/` 与 `_alt/` 为只读恢复证据；仅在调查历史构建中的未标记模块时，使用 `--discover --app-out <unpacked-build-directory>`。
